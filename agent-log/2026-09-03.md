# 2026-09-03

## Session — automation overview + Age Calculator page broken

**Asked:** how to run the `automation/` batch long-post pipeline, then how to
update already-published notes/long-posts, then investigated a live bug: the
`/age-calculator/` page (post 371) was rendering raw
CSS/JS/JSON-LD as visible plain text instead of a working widget.

**Found:**
- Neither `notes-factory` nor `long-post-factory` pipelines have an "update"
  path today — both `.github/workflows/publish-note.yml` and
  `publish-long-post.yml` only `POST` new drafts, and explicitly skip
  re-publishing a slug that already exists in `published-*/` (dedupe guard).
  Updating a live post currently has to go through direct WordPress access
  (the `claude-wp-mcp` plugin / MCP tools: `get_post` + `update_post` +
  `yoast_set_meta`), not through the GitHub Pages browser tools.
- Post 371 (`/age-calculator/`, live page) was last modified 2026-09-03
  13:24:16 — same day, cause not fully identified. Its raw `post_content` is
  bare CSS/JS/JSON-LD text with **no** `<style>`/`<script>` wrapper tags at
  all. Root cause: any save of `post_content` (Gutenberg Paragraph/Classic
  block, or a REST/API write) by a save path without the `unfiltered_html`
  capability gets run through `wp_kses_post`, which strips `<style>`/
  `<script>` tags — this is standard WP core behavior, not a security
  scanner (checked `list_plugins` — no Wordfence/Sucuri/scanner active).
  Confirmed no push/commit/update_post happened from this session before the
  bug was reported.
- `AgentLog.md` (project root, outside this repo) has fuller history on the
  Age Calculator page and the `enp_tool` CPT it belongs to — see
  the "Tools system (CPT-backed...)" section, session 2026-08-xx.

**Proposed but not yet built** (needs user sign-off before touching
`functions.php`/templates or deploying):
- Give the client a dedicated raw-code postmeta field (not `post_content`)
  for pasting AI-generated HTML/CSS/JS tool widgets, rendered via direct
  `echo` in the page template instead of `the_content()`. `update_post_meta`
  is never passed through `wp_kses_post`, so this survives regardless of who
  or what saves it (human, Gutenberg, REST, MCP).
- Deliberately **not** consolidating into the `enp_tool` CPT with a new
  permalink — that would need a 301 redirect from `/age-calculator/` and
  re-adding Rank Math meta + JSON-LD schema to avoid an SEO hit for no
  functional benefit. Keep the existing page/URL, just fix what field it
  renders from.
- Also proposed: hide/disable the visible content editor on this page in
  wp-admin so there's no accidental path back into `post_content`.
